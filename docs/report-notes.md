# CampusIQ: Project Report Notes

This document highlights critical considerations, architectural constraints, and evaluation metrics that should be accurately reflected in the final project report.

## 1. Differentiator & Novelty
**No single ML module within CampusIQ is claimed to be entirely novel.** 
- ATS resume scoring systems leveraging embeddings are common.
- RAG-based study chatbots are widely documented.
- Predicting at-risk students using ensemble models like XGBoost is standard educational data mining.

**The actual differentiator** of this project is the integration: bundling these four disparate modules into a single, cohesive, role-based platform. Specifically, the introduction of a **closed mentor intervention feedback loop** sets this apart from typical standalone prototypes. CampusIQ provides a unified workflow where data flows from prediction, to mentor dashboard, to intervention logging, and finally back into the system to measure the change in the student's risk profile over time.

## 2. The Intervention Loop (Correlation vs. Causation)
The mentor intervention loop calculates a student's `risk_before` and `risk_after` an intervention (e.g., academic tutoring or counseling) to measure success. 

**Important Limitation:** This demonstrates *correlation, not proof of causation*. While a student's risk score might decrease following a mentor's intervention, other external factors (such as the student simply studying more, easier assignments, or peer support) could explain the improvement. 

In the report, this must be framed purely as **"a signal for mentors"** to help track cohort progress and estimate intervention efficacy, rather than a strictly controlled scientific experiment proving the intervention *caused* the score change.

## 3. Privacy by Design: Role-Based Access
Academic risk data (e.g., the `placement_readiness` and `academic_risk` scores generated by the XGBoost predictor) is intentionally restricted to **mentor-only access**. 
- This is a deliberate privacy and ethical decision, not an oversight. 
- Exposing high-risk scores directly to struggling students can induce unnecessary anxiety and negatively impact morale (a self-fulfilling prophecy).
- The system is designed such that the AI operates in the background to empower mentors with cohort-wide analytics, while students interact only with constructive, forward-looking modules (the RAG Chatbot, Scheduler, and Resume Scorer).

## 4. Empirical Evaluation Metrics
The following metrics were achieved during the pipeline testing and should be cited in the report:

### A. Performance Predictor (XGBoost)
The model was tested on predicting at-risk students using synthetic historical data, optimizing for recall to ensure struggling students do not slip through the cracks.
- **Precision:** ~0.830
- **Recall:** 0.850
- **F1 Score:** 0.840

### B. Study Assistant (Local Phi-3-mini RAG)
The fully local RAG pipeline was evaluated using a strict 20-question groundedness test designed to measure hallucination rates.
- **Total Accuracy (Correctly Grounded):** 15 / 20 (75.0%)
  - *Answerable Questions:* 10 / 15 correct (The smaller model occasionally struggled with overly complex extraction formats).
  - *Unanswerable/Out-of-Scope Questions:* 5 / 5 correct (Strictly refused to hallucinate).
- **Anti-Hallucination Guardrail:** 100% effective. The model successfully recognized and refused all queries where the answer was not explicitly present in the provided document chunks.
